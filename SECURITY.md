# Reporting security issues

Do not post passwords, OAuth tokens, client secrets, private server addresses, personal databases or account exports in a public issue.

For a suspected security vulnerability, use GitHub's private vulnerability reporting option when available. Otherwise open a minimal issue asking for a private contact without including exploit details or sensitive information. Do not send private data until a private channel has been agreed.

Only the current release is the maintenance baseline. Do not assume old snapshots receive security backports. Provider permissions, consent and service security settings must be managed at the provider; the project does not offer a bypass.
